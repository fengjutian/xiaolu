## 1. 背景与目标

小鲁已经具备系统指标、硬件信息、传感器历史、SMART、驱动、事件日志、网络、软件、存储分析和独立工具等结构化数据。AI 能力的首要目标不是提供泛用聊天，而是把这些数据转化为可理解、可追溯、可验证的诊断结论，并在用户授权下编排经过审核的本地工具。

AI 在产品中的职责分为三层：

1. **解释**：用通俗语言说明指标、异常及其影响。
2. **编排**：根据问题选择并调用白名单内的只读检测能力。
3. **建议**：给出有证据和风险说明的下一步操作，但不替代本地规则和用户授权。

产品原则：**AI 负责解释和编排，规则引擎负责判定，受控工具负责执行，用户负责授权。**

## 2. 用户场景

### 2.1 健康报告解读

用户点击“AI 解读本机健康”，系统基于同一份诊断快照输出：

- 最值得关注的 1–3 个问题；
- 每个问题对应的证据、采集时间和数据来源；
- 风险等级与结论置信度；
- 建议执行的只读检查或人工操作；
- 数据不足、数据冲突和不可用原因。

### 2.2 自然语言追问

用户可以围绕当前快照追问，例如：

- 为什么电脑最近变慢？
- 这个磁盘是否需要更换？
- 游戏闪退更可能是温度、驱动还是内存问题？
- 哪些启动项可能影响开机速度？

回答必须绑定当前 `snapshotId`，不得把不同时间的状态混为同一结论。

### 2.3 引导式排障

在用户提出具体问题后，AI 可以生成只读检测计划，并按需调用经过审核的能力。例如“游戏经常闪退”可依次检查应用崩溃事件、GPU 驱动、温度历史、内存压力、磁盘空间和待重启状态。

调用前后均需展示当前进度；耗时任务必须支持取消。AI 不得执行任意 shell、PowerShell、注册表脚本或模型生成的可执行代码。

### 2.4 辅助修复（后期）

AI 可以为已有的受控写工具生成修复建议和执行预览，但必须遵守：

`发现问题 → 生成预览 → 展示依据/对象/风险 → 用户确认 → confirmationToken → 执行 → 结果验证 → 审计/回滚`

即使用户使用“一键优化”等表达，也不得跳过精确对象展示和二次确认。

## 3. 首个 AI MVP

### 3.1 范围

- 新增“AI 解读本机健康”入口；
- 读取当前系统快照、最近 24 小时趋势和现有诊断报告；
- 输出最多三个重点问题及证据、风险、建议、置信度；
- 支持围绕该快照连续追问；
- 允许调用白名单内的只读工具；
- AI 不可用时仍可查看原始数据和规则诊断结果；
- 支持云端模型适配器，并为后续本地模型预留统一接口。

### 3.2 不在 MVP 范围

- 自动清理文件、卸载软件、安装驱动或修改系统配置；
- AI 自由生成并执行命令、脚本或下载地址；
- 后台持续监听用户活动；
- 训练或微调用户私有数据；
- 对硬件寿命、故障时间作无依据的确定性预测；
- 用 AI 结论替换 SMART、温度阈值和安全规则引擎。

## 4. 输出协议

AI 的主要诊断输出必须是结构化数据，界面不得依赖对 Markdown 文本进行脆弱解析。

```ts
interface AiDiagnosticFinding {
  id: string;
  title: string;
  severity: "info" | "warning" | "critical";
  summary: string;
  confidence: "low" | "medium" | "high";
  evidenceRefs: string[];
  recommendations: AiRecommendation[];
  limitations: string[];
}

interface AiRecommendation {
  label: string;
  kind: "read_only_check" | "manual_action" | "controlled_write_preview";
  toolId?: string;
  risk: "none" | "low" | "medium" | "high";
  requiresConfirmation: boolean;
}
```

界面展示至少包含：结论、置信度、证据、限制和建议。没有证据引用的内容不得展示为确定性诊断。

## 5. 诊断事实与快照

新增统一的诊断事实模型，作为规则引擎、报告和 AI 的共同输入：

```ts
interface DiagnosticFact {
  id: string;
  snapshotId: string;
  category: string;
  severity: "info" | "warning" | "critical";
  title: string;
  value?: unknown;
  source: string;
  capturedAtUnixMs: number;
  confidence: number;
  availability: "available" | "unavailable" | "partial";
  evidenceRefs: string[];
  sensitive: boolean;
}
```

要求：

- 一次分析使用不可变 `snapshotId`；
- 数据标明来源、采集时间、可用性和置信度；
- 原始报告与发送给模型的数据分离保存；
- 模型只能看到经过策略筛选和脱敏的数据；
- 结论保留模型版本、提示词版本和证据引用，支持复查。

## 6. 工具调用协议

现有独立工具继续使用 `tool.json` 和 stdio JSON 通信，并为 AI 增加以下声明：

- 输入与输出 JSON Schema；
- `readOnly`、风险等级和所需权限；
- 是否允许 AI 自动调用；
- 超时、取消和并发限制；
- 敏感字段及脱敏策略；
- 写操作的预览、确认令牌、回滚和验证能力。

首版只允许 AI 自动调用 `readOnly: true` 且进入白名单的工具。工具 ID 和参数必须由宿主校验；模型不能指定可执行文件路径或任意命令行。

## 7. 模型适配架构

定义与具体厂商无关的 `AiProvider` 接口，至少覆盖：

- 流式对话；
- 结构化输出；
- 工具调用；
- 取消和超时；
- 模型能力探测；
- 请求大小和费用预估；
- 错误分类与重试策略。

支持三种运行方式：

1. **云端模型**：效果优先，用户显式启用并配置服务；
2. **本地模型**：隐私优先，后续按硬件能力评估；
3. **无 AI 模式**：所有原始检测、规则诊断和工具功能保持可用。

模型不可直接访问 Tauri command、文件系统或网络；所有能力必须经宿主的工具网关调用。

## 8. 隐私与联网

- AI 默认关闭，首次启用前说明将发送的数据类型、服务商和用途；
- 默认不发送序列号、硬件 ID、主机名、用户名、MAC、IP、完整本地路径、进程命令行和事件日志全文；
- 发送前提供数据摘要或预览，并允许取消；
- API 密钥使用系统安全凭据存储，不写入普通设置文件和日志；
- 云端请求与应用更新、遥测使用独立开关；
- 不以用户诊断数据训练模型，除非用户获得独立、明确且可撤回的授权；
- AI 会话和诊断记录默认本地保存，支持单条删除和全部清除；
- 网络失败或用户拒绝上传时自动退回规则诊断，不阻断应用。

## 9. 安全与防护

- 系统提示词、模型响应和外部数据均视为不可信输入；
- 事件日志、文件名、软件名称等内容不得改变工具权限和系统指令；
- 工具网关实施固定白名单、参数 Schema、超时、速率限制和审计；
- 写工具始终要求本地 UI 二次确认，模型文本不能视为授权；
- 健康阈值、风险等级、权限和回滚条件由本地代码决定；
- 模型拒绝或输出格式错误时展示可恢复错误，不伪造诊断结果；
- 高风险建议必须提醒备份、恢复点或人工服务渠道。

## 10. 可观测性与评测

在用户允许的本地诊断日志中记录：

- 脱敏后的事实 ID，不默认记录完整原始值；
- 模型、提示词和事实 Schema 版本；
- 工具调用、参数摘要、耗时和结果；
- 输出校验失败、重试和降级原因；
- 用户对结论“有帮助/无帮助/不准确”的反馈。

上线前建立固定脱敏样本集，至少覆盖正常系统、过热、磁盘健康异常、内存压力、驱动异常、网络故障、数据缺失和相互冲突的信号。

## 11. 验收标准

### 11.1 MVP 功能验收

1. AI 回答中的每个确定性问题至少引用一个有效 `evidenceRef`。
2. 切换或刷新快照后，旧回答明确标记为历史结果，不引用新数据。
3. 关闭云端 AI 后不产生任何模型服务网络请求。
4. 脱敏策略能从发送载荷中移除定义的敏感字段。
5. 模型不可用、超时或格式错误时，规则诊断和原始报告仍可使用。
6. 首版 AI 无法调用写工具，无法通过参数绕过工具白名单。
7. 用户可以取消流式回答和正在执行的只读检查。

### 11.2 质量门槛

- 固定诊断集的证据引用有效率为 100%；
- 高风险事实不得被回答为“正常”；
- 不得在数据缺失时编造温度、寿命、驱动版本或修复结果；
- 结构化输出解析失败时最多重试一次，之后明确降级；
- AI 引入后不增加主应用常驻管理员权限。

## 12. 里程碑

| 阶段 | 交付内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| AI-0 基础 | 诊断事实、快照、脱敏、Provider 接口 | Schema 与隐私评审通过 |
| AI-1 MVP | 健康解读、证据引用、追问、云端模型适配 | 固定诊断集和失败降级测试通过 |
| AI-2 排障 | 只读工具白名单、检测计划、进度和取消 | 工具注入与越权测试通过 |
| AI-3 本地化 | 本地模型适配、能力探测和性能降级 | 支持硬件矩阵测试通过 |
| AI-4 辅助修复 | 写操作预览、确认、验证、审计和回滚 | 每项写工具单独安全评审通过 |
