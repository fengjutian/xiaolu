## 1. 产品定义

一句话目标：

> **功能对标鲁大师的核心使用场景；无捆绑、无广告、完全免费、默认安全可回滚、不收集用户信息。**

“对标”指用户能获得同等结果，不指复制其代码、商标、文案、私有协议、驱动或评分算法。鲁大师的分数、排名和“一键优化”结果不作为本产品的验收基准。

### 1.1 目标用户与核心场景

| 场景 | 用户要的结果 | 本产品对应能力 |
|---|---|---|
| 看配置 | 一分钟看清 CPU、显卡、内存、硬盘、主板、显示器、电池 | 硬件检测与概览 |
| 看健康 | 温度、磁盘 SMART、电池损耗、驱动异常 | 传感器、存储健康、驱动检测 |
| 看性能 | 跑分、单项原始指标、历史对比 | CPU/内存/磁盘/GPU 跑分 |
| 做维护 | 清理、优化、启动项、驱动更新、空间分析 | 25 个工具箱工具 |
| 出报告 | 可脱敏、可分享的诊断报告 | JSON / Markdown / HTML |

### 1.2 与鲁大师的分界线

本产品**只做工具，不做全家桶**：

- 不捆绑任何第三方软件，不弹广告，不劫持主页，不静默升级；
- 不设账号体系，不设会员加速，不设付费墙；
- 默认不联网、不上传硬件标识、不做默认遥测；
- 不装内核驱动、不做进程注入、不做 Explorer 注入；
- 不提供来源不明的驱动包，不绕过 Windows 签名机制。

## 2. 四条硬约束（验收否决项）

任一版本违反以下任意一条，不得发布：

1. **无捆绑**：安装包、升级包、工具箱内不得出现未在界面明示的第三方软件。
2. **免费**：所有已发布功能不设付费、会员、点数或广告解锁。
3. **安全**：写操作必须“预览 → 二次确认 → 执行 → 可回滚（或明确标注不可逆）”；默认普通用户权限；提权操作独立进程并留痕。
4. **不收集**：默认零遥测、零上传；任何联网行为必须由用户显式触发，并在界面说明目标、内容和用途。

补充否决项：

- 默认安装内核驱动或后台服务；
- 未告知的联网请求；
- 写操作没有确认令牌或审计日志；
- 声称与鲁大师分数“等价”或“可换算”。

## 3. “媲美”的判定原则

| 原则 | 说明 | 反例 |
|---|---|---|
| 结果等价 | 用户能得到同样的结论或同样的维护效果 | 只显示“建议清理”，不提供清理 |
| 手段更干净 | 用公开 API、官方渠道、可回滚方案 | 用私有驱动读传感器、用黑盒规则改注册表 |
| 可解释 | 每项结论有来源、时间、原因、置信度 | “系统评分 98 分”但无计算依据 |
| 可退出 | 用户能撤销、卸载、关闭 | 装完常驻、无法关闭 |
| 诚实 | 数据不可用就说不可用 | 用估算值冒充真实温度 |

**“一键”不是黑盒**：一键 = 一组可预览、可勾选、可回滚的变更集合，不是“点一下不知道改了什么”。

## 4. 能力分级（L0–L4）

所有工具和模块统一用以下级别描述，验收也按级别判定。

| 级别 | 名称 | 定义 | 必须满足 |
|---|---|---|---|
| **L0** | 只读 | 只扫描、只展示，零写入 | 来源、时间、不可用原因可见 |
| **L1** | 单点执行 | 预览 → 确认 → 执行单项 → 显示结果 | 确认令牌、审计日志、失败原因 |
| **L2** | 可回滚 | 执行前记录原值或备份，提供还原动作 | 还原成功率达标签值；还原入口可发现 |
| **L3** | 批量与恢复点 | 多选/一键，失败隔离，执行前后 diff | 单项失败不影响其他项；可生成恢复点 |
| **L4** | 闭环 | 检测 → 建议 → 执行 → 复检 → 回滚全链路 | 证据链完整；复检结果与预期一致 |

说明：

- 只读工具不是“低人一等”。**memopt_pro、privacy_incognito、intercept_bs 明确长期停留在 L0**，因为“强制释放内存”“清除痕迹”“安装监控”要么是伪优化，要么不可逆、要么需要常驻后端。
- 输出型工具（压缩、PDF、锁屏）不要求回滚，但必须保证“不破坏原文件”或“操作可预期”。

## 6. 25 个工具：现状、目标与优先级

### 6.1 总览

- 25 个独立工具进程：**6 个纯只读 + 19 个含写操作**（`tool.json` 的 `risk` 实测为 read_only 6 / write 13 / system 6）；另有 4 个应用内页面（护眼、快捷启动、桌面助手等）。
- 安全画像（按 `tool.json` 实测）：**仅 `driver_manager` 声明联网**，其余 24 个默认离线；提权 helper 已实现（系统启动项、服务启动类型、计划任务、受限传感器、碎片整理、Hosts、崩溃转储模式、HKLM 设置、卷扩展、还原点、处理器限功率、电源计划与电源设置写入）。
- 19 个含写操作的工具中，**11 个有回滚字段**（`adblock_master=custom`、`ai_cooling=custom`、`bsod_repair=custom`、`cclean=recycle_bin`、`clean_master=recycle_bin`、`DuplicateFileClean=recycle_bin`、`pc_optimizer=custom`、`privacy_protection=custom`、`software_pm=custom`、`sys_boost=custom`、`winopt_assistant=custom`）；`proc_opt` 的结束进程不可逆，`lockscreen`、`omni_zip`、`master_pdf`、`gpu_opt` 属于一次性动作或输出型。
- `permissions.elevation` 只有真正需要提权才能工作的工具才标 `uac`（当前：`pc_optimizer`）；部分动作才需要提权的工具（`winopt_assistant`、`software_pm`、`sys_clean`、`bsod_repair`、`adblock_master`、`ai_cooling`）仍标 `none`，由界面在动作按钮上标注「需 UAC」，避免整个工具被误标成必须管理员运行。

排序原则：**用户感知频率 × 可逆性 × 实现成本**。先做“高频、可逆、成本低”的，再做“高风险、需提权”的。

- 决定（2026-11-08）：跑分的「基线 / 复检 / 可信度」必须由**同机同版本**的历史记录算出，不能引入跨机排行榜或上传样本（与「不收集数据」的硬约束冲突）。计算逻辑放 Rust 侧（`src-tauri/src/benchmark.rs`），前端只渲染；前端目前零测试框架，纯计算逻辑放前端无法被单测覆盖。
- 验收：
  - 写操作后界面有可见回执；✅ 软件清单卸载：浏览器演示模式实测，点「卸载」后出现「已启动系统卸载程序」提示条（修复前无任何提示）
  - 执行中不允许重复触发同一操作；✅ 卸载期间该行按钮 loading、其余行禁用
  - 失败原因来自真实错误文本，不编造；✅ Rust `launch_uninstall` 的中文原因直传界面，单测 `refuses_to_launch_uninstallers_outside_the_whitelist` 覆盖「白名单外 / 格式错 / 键不存在」三条路径
  - 前端不存在只写不读、只读不写的状态；✅ `useState` 扫描：死状态 0 处、never-set 0 处
  - 未捕获的 Promise rejection 视为缺陷；✅ 主应用 40+ 个交互入口逐个审过：直接调 API 而没有 try/catch 的只剩后台轮询类调用（护眼休息提醒、传感器告警推送），它们不影响面板本身的可见反馈
  - 跑分基线可复算、可解释；✅ Rust 单测 7 项（中位数与波动、跨应用版本不混入、旧记录无环境信息不参与、样本不足判定、只取最近 10 次、波动带内/带外判定、只与同项目同版本基线配对）；宿主单测合计 143 passed / 0 failed
  - 界面证据（浏览器演示模式实测）：跑分页出现「本机基线与可信度」表（CPU 单核 6 次样本 / 基线 8560 分 / 波动 ±1.4% / 可信度「高」；磁盘顺序读写 2 次样本 / 可信度「样本不足」）；跑完一次后卡片内出现绿色回执「对比本机基线 8560 分 · +0.0% · 落在基线 ±2.0% 波动带内」，按钮变为「复检并对比基线」；控制台 0 条 error/warn

## 9. 明确不做

- 与鲁大师分数一一对应，或宣称可换算；
- 使用/兼容鲁大师私有驱动、私有协议、私有规则库；
- 内核级广告过滤、进程注入、Explorer/任务栏注入；
- 静默安装驱动、静默升级、静默联网；
- 云端排名（需要上传硬件与分数）；
- 强制释放内存、清理注册表“加速”、无差别注册表模板；
- 账号体系、会员加速、广告解锁；
- 来源不明的驱动包或 DLL 下载站。

## 10. 风险与待决

| 风险 | 影响 | 处理 |
|---|---|---|
| 传感器 helper 依赖 Ring0 驱动，可能被 Defender 拦截 | CPU/主板温度覆盖不足 | 可选安装、签名校验、明确风险、可卸载；默认不装 |
| 提权 helper 扩大攻击面 | 安全约束被突破 | 独立进程、IPC 白名单、固定参数、审计 |
| 跑分无可信基线 | “媲美”缺乏说服力 | 先做同机重复性与原始指标，不承诺跨机排名 |
| 工具数量多、维护成本高 | 质量下降 | 一工具一 crate、共享协议库、统一验收 |

待决事项：

1. 传感器 helper 是否采用 LibreHardwareMonitor/PawnIO，需完成许可、签名、AV 误报、回滚四项评审（见 [SENSOR_HELPER_DESIGN.md](SENSOR_HELPER_DESIGN.md)）。
2. 跑分是否提供“可选匿名基线贡献”，默认关闭。
3. `c_expand` 是否长期只做诊断，不开放实际扩盘。
