版本：v0.1（2026-11-06）  
适用范围：小鲁 · System Lens 0.52.0 及后续版本  
关联文档：[完整功能规划](FULL_FEATURE_ROADMAP.md)、[模块 REA 分析](REA_SUPERAPP_MODULE_ANALYSIS.md)、[工具包规范](TOOL_PACKAGE_SPEC.md)

## 1. 产品定义

一句话目标：

> **功能对标鲁大师的核心使用场景；无捆绑、无广告、完全免费、默认安全可回滚、不收集用户信息。**

“对标”指用户能获得同等结果，不指复制其代码、商标、文案、私有协议、驱动或评分算法。鲁大师的分数、排名和“一键优化”结果不作为本产品的验收基准。

### 1.1 目标用户与核心场景

| 场景 | 用户要的结果 | 本产品对应能力 |
|---|---|---|
| 看配置 | 一分钟看清 CPU、显卡、内存、硬盘、主板、显示器、电池 | 硬件检测与概览 |
| 看健康 | 温度、磁盘 SMART、电池损耗、驱动异常 | 传感器、存储健康、驱动检测 |
| 看性能 | 跑分、单项原始指标、历史对比 | CPU/内存/磁盘/GPU 跑分 |
| 做维护 | 清理、优化、启动项、驱动更新、空间分析 | 25 个工具箱工具 |
| 出报告 | 可脱敏、可分享的诊断报告 | JSON / Markdown / HTML |

### 1.2 与鲁大师的分界线

本产品**只做工具，不做全家桶**：

- 不捆绑任何第三方软件，不弹广告，不劫持主页，不静默升级；
- 不设账号体系，不设会员加速，不设付费墙；
- 默认不联网、不上传硬件标识、不做默认遥测；
- 不装内核驱动、不做进程注入、不做 Explorer 注入；
- 不提供来源不明的驱动包，不绕过 Windows 签名机制。

## 2. 四条硬约束（验收否决项）

任一版本违反以下任意一条，不得发布：

1. **无捆绑**：安装包、升级包、工具箱内不得出现未在界面明示的第三方软件。
2. **免费**：所有已发布功能不设付费、会员、点数或广告解锁。
3. **安全**：写操作必须“预览 → 二次确认 → 执行 → 可回滚（或明确标注不可逆）”；默认普通用户权限；提权操作独立进程并留痕。
4. **不收集**：默认零遥测、零上传；任何联网行为必须由用户显式触发，并在界面说明目标、内容和用途。

补充否决项：

- 默认安装内核驱动或后台服务；
- 未告知的联网请求；
- 写操作没有确认令牌或审计日志；
- 声称与鲁大师分数“等价”或“可换算”。

## 3. “媲美”的判定原则

| 原则 | 说明 | 反例 |
|---|---|---|
| 结果等价 | 用户能得到同样的结论或同样的维护效果 | 只显示“建议清理”，不提供清理 |
| 手段更干净 | 用公开 API、官方渠道、可回滚方案 | 用私有驱动读传感器、用黑盒规则改注册表 |
| 可解释 | 每项结论有来源、时间、原因、置信度 | “系统评分 98 分”但无计算依据 |
| 可退出 | 用户能撤销、卸载、关闭 | 装完常驻、无法关闭 |
| 诚实 | 数据不可用就说不可用 | 用估算值冒充真实温度 |

**“一键”不是黑盒**：一键 = 一组可预览、可勾选、可回滚的变更集合，不是“点一下不知道改了什么”。

## 4. 能力分级（L0–L4）

所有工具和模块统一用以下级别描述，验收也按级别判定。

| 级别 | 名称 | 定义 | 必须满足 |
|---|---|---|---|
| **L0** | 只读 | 只扫描、只展示，零写入 | 来源、时间、不可用原因可见 |
| **L1** | 单点执行 | 预览 → 确认 → 执行单项 → 显示结果 | 确认令牌、审计日志、失败原因 |
| **L2** | 可回滚 | 执行前记录原值或备份，提供还原动作 | 还原成功率达标签值；还原入口可发现 |
| **L3** | 批量与恢复点 | 多选/一键，失败隔离，执行前后 diff | 单项失败不影响其他项；可生成恢复点 |
| **L4** | 闭环 | 检测 → 建议 → 执行 → 复检 → 回滚全链路 | 证据链完整；复检结果与预期一致 |

说明：

- 只读工具不是“低人一等”。**memopt_pro、privacy_incognito、intercept_bs 明确长期停留在 L0**，因为“强制释放内存”“清除痕迹”“安装监控”要么是伪优化，要么不可逆、要么需要常驻后端。
- 输出型工具（压缩、PDF、锁屏）不要求回滚，但必须保证“不破坏原文件”或“操作可预期”。

## 6. 25 个工具：现状、目标与优先级

### 6.1 总览

- 25 个独立工具进程：**19 个只读 + 6 个可写**；另有 4 个应用内页面（护眼、快捷启动、桌面助手等）。
- 安全画像（按 `tool.json` 实测）：**仅 `driver_manager` 声明联网**，其余 24 个默认离线；全部 `elevation: none`，高风险提权 helper 尚未实现。
- 6 个写工具中，**3 个有回滚字段**（`clean_master=recycle_bin`、`pc_optimizer=custom`、`software_pm=custom`）；`lockscreen`、`omni_zip`、`master_pdf` 属于一次性动作或输出型，不要求回滚。

排序原则：**用户感知频率 × 可逆性 × 实现成本**。先做“高频、可逆、成本低”的，再做“高风险、需提权”的。

### 6.2 P0：立即优化（2 周，6 个）

#### 1. clean_master（清理大师）L2 → L3（0.2.0 已补执行明细）

- 现状：9 类固定白名单扫描、勾选清理、文件移入回收站；0.2.0 起逐文件记录结果并写入本地完整清单。
- 缺口：无还原按钮、无批量预设、无执行前后可视化 diff。
- 验收：
  - 清理后生成逐文件清单（路径、大小、结果、失败原因）；✅ 0.2.0
  - 回收站还原成功率 ≥ 95%，且界面有“还原”入口；⏳ 清单与路径已就绪，还原入口待做
  - 被占用/无权限文件跳过并逐项说明，不中断整批；✅ 0.2.0（256 个一批，失败自动逐文件重试）
  - 白名单外写入为 0；✅
  - 1 GiB 候选量下 P95 ≤ 60 秒（SSD）；⏳ 待实测

#### 2. pc_optimizer（电脑性能优化）L2 → L3（0.2.0 已补逐项复核与撤销）

- 现状：电源计划切换 + 逐项电源设置读写；0.2.0 起每项独立写入、独立回读，结果附带一次性“撤销本次修改”令牌，并写入本地快照。
- 缺口：无批量预设；无系统恢复点（电源设置可逐项还原，暂不需要）。
- 验收：
  - 切换/还原后 `powercfg /getactivescheme` 与逐项值一致；✅ 切换后有回读校验
  - 每项原值、执行时间、结果可查；✅ 操作日志 + `pc_optimizer/run-*.json` 快照
  - 单项失败不影响其余项；✅ 0.2.0 逐项隔离
  - 审计覆盖率 100%；✅
  - 一键撤销本次修改；✅ 0.2.0（结果页按钮）

#### 3. software_pm（软件权限管理）L2 → L3（0.3.0 已补批量与一键还原）

- 现状：启动项/服务/计划任务/通知只读；当前用户启动项可逐项或批量启停，0.3.0 起支持“恢复全部停用项”，逐项回读并写入快照。
- 缺口：系统级启动项（HKLM）、服务、计划任务仍只读，需要独立提权 helper。
- 验收：
  - 用户级启停登录后生效，且可一键还原；✅ 0.3.0（逐项 + 全部恢复）
  - 系统级操作必须 UAC + 独立 helper，不得在宿主直接提权；⏳ 待实现 helper
  - 服务/计划任务修改逐项确认，并记录原值；⏳ 待实现 helper
  - 单项失败不影响其他项；✅ 0.3.0

#### 4. winopt_assistant（Windows 优化助手）L0 → L2（0.2.0 已补 5 项 HKCU 应用与撤销）

- 现状：11 项系统设置体检；0.2.0 起视觉效果、透明效果、窗口动画、存储感知、游戏模式可逐项应用、回读与撤销。
- 缺口：休眠、快速启动、诊断数据、系统还原、长路径、Windows 搜索仍在 HKLM/服务层，需要提权 helper。
- 验收：
  - 每项可单独应用、单独还原；✅ 5 项 HKCU
  - 原值写入日志，还原后与执行前一致；✅ 快照 + 一次性撤销令牌
  - 只改体检项，不引入注册表模板；✅
  - 6 项需管理员的设置可应用；⏳ 待 helper

#### 5. gpu_opt（显卡性能优化）L0 → L1

- 现状：显卡、驱动日期、电源计划与建议。
- 缺口：无动作。
- 验收：
  - 可切换电源计划、设置每应用 GPU 首选项；
  - 不做“神秘一键优化”，不批量写注册表；
  - 变更可还原。

#### 6. defrag（磁盘碎片整理）L0 → L2

- 现状：固定卷、物理介质、容量、TRIM 状态只读。
- 缺口：不执行整理或 TRIM。
- 验收：
  - HDD 调用 Windows 官方碎片整理 API，可取消、有进度；
  - SSD 只发 TRIM，不做传统整理；
  - 执行前后碎片率/TRIM 状态可见；
  - 失败原因明确（权限、卷类型、占用）。

### 6.3 P1：第二批（2–3 周，6 个）

#### 7. sys_boost（系统优化大师）L0 → L2

- 只读汇总 → 白名单优化项执行 + 恢复点；禁止无差别注册表模板。
- 验收：每项可预览、可回滚；恢复点创建成功才允许批量执行。

#### 8. cclean（C 盘瘦身）L0 → 合并/升级

- 与 clean_master 共享扫描逻辑，避免两套白名单；或直接升级为可执行版。
- 验收：两者结果一致；删除重复实现。

#### 9. DuplicateFileClean（重复文件清理）L0 → L1

- 现状：按大小 + FNV-1a 分组，只读统计。
- 目标：选择保留项，其余移入回收站。
- 验收：只处理 ≥ 1 MiB；保留策略明确；移入回收站可还原；不删除目录外文件。

#### 10. privacy_clean（隐私清理）L0 → L1

- 范围限定为缓存/临时文件；**不清浏览器历史、Cookie、密码**。
- 验收：逐项勾选；明确标注“不可回滚”；不触碰用户文档。

#### 11. privacy_protection（隐私保护）L0 → L1

- 遥测级别、广告 ID、权限开关的读写，原值备份。
- 验收：每项可还原；不修改安全策略外的键。

#### 12. proc_opt（电脑智能防卡顿）L0 → L1

- 结束进程、调整优先级需二次确认；不做注入、不写其他进程内存。
- 验收：系统关键进程禁止操作；操作留痕；失败原因可见。

### 6.4 P2：第三批（3–4 周，6 个）

#### 13. driver_manager（驱动管理）L0 → L2

- 检测与 WU 预检已有；补官方来源下载、签名校验、安装、回滚。
- 验收：只走 Windows Update/厂商官网；安装前展示版本与硬件匹配；失败可回滚；独立 helper。

#### 14. dll_repair（DLL 修复）L0 → L1

- 只检测缺失并引导安装官方运行库，**不下载单个 DLL**。
- 验收：不写入系统目录；来源为微软官方；可撤销。

#### 15. bsod_repair（蓝屏修复）L0 → L1

- 补转储设置与只读分析建议；不自动改内核参数。
- 验收：设置项可还原；分析结论引用事件证据。

#### 16. sys_clean（Windows 系统瘦身）L0 → L1

- 白名单 Appx 移除，执行前要求系统还原点。
- 验收：逐项确认；移除清单可导出；不碰系统关键包。

#### 17. adblock_master（广告拦截）L0 → L1

- 只做 Hosts 备份写入与还原；不做驱动/WFP 过滤。
- 验收：写入前备份原 Hosts；一键还原；规则来源可查。

#### 18. ai_cooling（AI 智能降温）L0 → L1

- 只调电源计划/进程优先级，不碰风扇/EC。
- 验收：建议有温度与负载证据；执行可回滚。

### 6.5 P3：高风险（4 周以上，3 个）

#### 19. c_expand（C 盘扩容）L0 → L3

- 独立提权 helper；备份、BitLocker 检查、供电检查、恢复介质提示。
- 验收：默认不执行；必须显式确认；失败可恢复；不触碰系统保留分区。

#### 20. omni_zip（压缩工具）L1 → L2

- 补进度、取消、ZIP64、超大文件与覆盖策略。
- 验收：10 GiB 包可完成/取消；Zip-Slip 防护回归测试通过。

#### 21. master_pdf（PDF 大师）L1 → L2

- 补页面级预览、加密/权限、输出命名冲突策略。
- 验收：不修改原文件；输出可打开；页数/旋转结果可验证。

| 扫描 P95 超时率 | 未统计 | < 1% |

“未统计”项在 M1 内补埋点，不靠主观判断。

## 9. 明确不做

- 与鲁大师分数一一对应，或宣称可换算；
- 使用/兼容鲁大师私有驱动、私有协议、私有规则库；
- 内核级广告过滤、进程注入、Explorer/任务栏注入；
- 静默安装驱动、静默升级、静默联网；
- 云端排名（需要上传硬件与分数）；
- 强制释放内存、清理注册表“加速”、无差别注册表模板；
- 账号体系、会员加速、广告解锁；
- 来源不明的驱动包或 DLL 下载站。

## 10. 风险与待决

| 风险 | 影响 | 处理 |
|---|---|---|
| 传感器 helper 依赖 Ring0 驱动，可能被 Defender 拦截 | CPU/主板温度覆盖不足 | 可选安装、签名校验、明确风险、可卸载；默认不装 |
| 提权 helper 扩大攻击面 | 安全约束被突破 | 独立进程、IPC 白名单、固定参数、审计 |
| 跑分无可信基线 | “媲美”缺乏说服力 | 先做同机重复性与原始指标，不承诺跨机排名 |
| 工具数量多、维护成本高 | 质量下降 | 一工具一 crate、共享协议库、统一验收 |

待决事项：

1. 传感器 helper 是否采用 LibreHardwareMonitor/PawnIO，需完成许可、签名、AV 误报、回滚四项评审（见 [SENSOR_HELPER_DESIGN.md](SENSOR_HELPER_DESIGN.md)）。
2. 跑分是否提供“可选匿名基线贡献”，默认关闭。
3. `c_expand` 是否长期只做诊断，不开放实际扩盘。
